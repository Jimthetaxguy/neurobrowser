# NeuroBrowser Project

Updated: 2026-05-22

## Vision

NeuroBrowser is an AI-native desktop browser experiment: a Rust browser/agent
core with a native desktop control surface that lets an assistant inspect pages,
propose browser actions, and execute approved workflows.

The current project goal is not to run the product inside Chrome. The desktop
app should own the browser runtime. The immediate goal is to make the Rust-owned
agent, action-policy, provider, and page-state contracts real and testable
behind a Tauri desktop shell.

The implementation is also not a full custom HTML/CSS rendering engine today.
Rendered pages run through native desktop webviews, while the Rust core handles
fetching, parsing, snapshots, tools, providers, and agent policy.

## Current Architecture

Primary path:

- React control surface under `src-tauri/src/`
- Tauri v2 desktop wrapper under `src-tauri/`
- Rust command and runtime bridge in `src-tauri/src/main.rs` and
  `src-tauri/src/runtime.rs`
- Core Rust library under `src/`
- Real provider adapters for OpenAI, Anthropic, and Ollama

Secondary spike:

- Swift/AppKit host under `NeuroBrowser/`
- React sidebar bundle generated by `npm run build:appkit`
- Native `WKWebView` page host used to evaluate AppKit as a future ceiling

Accepted frontend decision:

- React + Tauri is primary.
- AppKit remains a parity spike until page identity, provider bridging,
  snapshots, and agent calls reach the Rust contract.
- Objective-C and Objective-C++ are not part of the current path.

See [docs/adr/ADR-001-react-tauri-primary.md](docs/adr/ADR-001-react-tauri-primary.md).

## Real Systems

Provider configuration is environment-driven:

- OpenAI: `OPENAI_API_KEY`, optional `OPENAI_MODEL`
- Anthropic: `ANTHROPIC_API_KEY`, optional `ANTHROPIC_MODEL`
- Ollama: `OLLAMA_BASE_URL`, optional `OLLAMA_MODEL`

Production app paths must fail closed when a provider, host bridge, or native
runtime is unavailable. Do not add mock provider responses or hardcoded fixture
routes outside tests.

## Verification Gate

Use `./verify.sh` before claiming the repo is ready. The gate runs Rust format,
clippy, tests, the Tauri frontend build, the Tauri cargo check, and a release
build.

For focused frontend work, also run:

```bash
cd src-tauri
npm run build
npm run build:appkit
```

For native AppKit work, add:

```bash
xcodebuild -list -project NeuroBrowser.xcodeproj
xcodebuild build -project NeuroBrowser.xcodeproj -scheme NeuroBrowser -configuration Debug CODE_SIGNING_ALLOWED=NO
```

Chrome/Playwright validation is acceptable only for React-shell layout smoke
testing and fail-closed host-bridge checks. It is not a substitute for native
Tauri runtime validation.
